> 這篇整理 Claude Code「在對話視窗打 `/` 觸發的內建指令」。指令很多,但 90% 的時間其實只會用到最前面那幾個。內容對應官方文件(約 2026-06 版本),指令會隨版本演進,以官方文件為準。

## 最常用的核心指令

這幾個建議直接記起來,其他用到再查就好。

### `/clear` — 開一張乾淨的新對話

把目前對話脈絡清空、重新開始(舊對話還在,沒刪掉)。

**情境**:剛跟 Claude 弄完一個登入 bug,現在想問完全不相關的新功能。與其讓它被前面一堆對話干擾、還浪費「腦容量」,不如 `/clear` 從乾淨狀態開始。

### `/compact` — 把太長的對話濃縮成摘要

對話快塞滿,但你還需要前面的脈絡,它會壓縮成重點摘要再繼續。

**情境**:同一個任務做了一兩小時、改了十幾個檔案。對話長到快爆,但不能 `/clear`(會失憶)。`/compact` 保留「做了什麼、決定了什麼」,釋放空間繼續做。

### `/context` — 看「腦容量」被什麼佔用

畫出一張彩色格子圖,顯示目前上下文的佔用狀況。

**情境**:覺得變慢或快滿了,想知道是被某個超大檔案吃掉、還是對話太長。一看就知道,還會給優化建議。

### `/rewind` — 時光倒流回到存檔點

把「對話」和「程式碼」一起倒退回先前的檢查點。

**情境**:Claude 改了三個檔案,結果整個方向走錯。直接 `/rewind` 像遊戲讀取存檔,回到動手前的乾淨狀態重來。

### `/model` — 切換要用哪個模型

換成更強或更省的模型,並記住當作之後的預設。

**情境**:整理文件、改錯字這種雜事切到快又省的模型;遇到複雜架構設計切到最強的 Opus。

### `/resume` — 接續之前的對話

用名稱或選單叫回先前的 session 繼續做。

**情境**:昨天做到一半關掉電腦,今天 `/resume` 把舊對話整個叫回來,不用從頭交代。

### `/init` — 讓 Claude 認識這個專案

掃描整個專案,自動產生一份 `CLAUDE.md`(專案說明書)。

**情境**:剛 clone 一個陌生 repo,想讓 Claude 了解架構、慣例、怎麼跑測試。

### `/memory` — 編輯 Claude 的長期記憶

編輯 `CLAUDE.md`,讓某些規則「永久記住」。

**情境**:希望 Claude 永遠記得「主線是 `main`、測試用 `pnpm test`、回覆用繁中」,就寫進這裡。

### `/cost`、`/usage` — 看這次花了多少

顯示目前 session 的花費、用量與方案額度。

**情境**:做完一個大任務,想確認燒了多少 token、離方案上限還有多遠。

### `/help` — 忘記指令時的萬用救星

列出所有可用指令。不確定有沒有某功能、或忘記指令名稱,先打它看一眼。

## 程式碼審查與品質

| 指令 | 白話說明 | 什麼時候用 |
|------|---------|-----------|
| `/code-review` | 檢查你改的 diff 有沒有 bug、可簡化處;可加 `--fix` 直接套修正 | 寫完功能、發 PR 前先自我體檢 |
| `/simplify` | 只找「可以更簡潔、更有效率」的地方並修掉(不抓 bug) | 程式能跑但想讓它更乾淨時 |
| `/review` | 在本機審查一個 PR | 同事發了 PR,想讓 Claude 幫看 |
| `/security-review` | 專門掃安全漏洞(注入、權限、資料外洩等) | 上線前的資安檢查 |

## 執行與驗證

| 指令 | 白話說明 | 什麼時候用 |
|------|---------|-----------|
| `/run` | 實際把你的 app 跑起來看改動有沒有效 | 改完功能,想眼見為憑而非只看程式碼 |
| `/verify` | 建置 + 執行 + 觀察結果,確認真的修好了 | 宣稱「修好了」之前先驗證 |
| `/diff` | 開互動式檢視器看「還沒 commit 的改動」 | 想逐項確認自己改了哪些東西 |

## 規劃與大型任務

| 指令 | 白話說明 | 什麼時候用 |
|------|---------|-----------|
| `/plan` | 進入「計畫模式」,先想清楚策略再動手 | 複雜任務,怕 Claude 亂衝先讓它規劃 |
| `/branch` | 在當前點「分岔」對話,試不同方向又不丟原本的 | 想平行嘗試兩種解法做比較 |
| `/fork` | 派一個背景分身去執行某指令,結果回傳主對話 | 想同時間進行一件獨立的事 |
| `/deep-research` | 上網多方搜尋、交叉查證、產出有引用的報告 | 要深入研究一個陌生主題 |

## 其餘實用 / 趣味指令(用到再查)

- `/skills`:列出可用的 skills
- `/plugins`:管理外掛;`/reload-skills`、`/reload-plugins`:重新載入新建的 skill / 外掛
- `/effort`:調整思考力道(low → max),難題給多一點推理時間
- `/schedule`:建立定時自動任務;`/loop`:每隔一段時間重複跑某指令
- `/autofix-pr`:CI 失敗或有人留言時,自動推修正到 PR
- `/install-github-app`、`/install-slack-app`、`/chrome`:接 GitHub Actions / Slack / 瀏覽器
- `/release-notes`:看更新了什麼;`/powerup`:互動課程學新功能;`/insights`:用量分析報告
- `/radio`(lo-fi 背景音樂)、`/stickers`(訂貼紙)、`/passes`(分享免費週)、`/color`、`/scroll-speed`、`/tui`:小調整與趣味功能
- `/mobile`、`/ios`、`/android`、`/desktop`:跨裝置 / 換到桌面 app

## 釐清:三種「指令」其實不一樣

很多人會搞混,這裡一次講清楚。

**1. 內建 `/` 指令**(本篇主角):在對話視窗打 `/` 觸發,**立刻生效**、不用重開。例:`/clear`、`/model`、`/config`。

**2. 自訂 `/` 指令(Skills)**:你或專案自己建立的擴充功能,放在 `.claude/skills/<名稱>/SKILL.md`。打 `/skills` 可列出來看。

**3. CLI 啟動參數(flags)**:在終端機**啟動 Claude 之前**就帶上的設定,中途不能改(要改得重開):

```bash
claude --model claude-opus --add-dir /path/to/project
claude -c          # 接續最近一次對話
claude --debug
```
